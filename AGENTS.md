## Commit messages

Follow Conventional Commits 1.0.0 for every commit and pull request title.
Use `feat` for features, `fix` for bug fixes, and mark breaking changes with
`!` or a `BREAKING CHANGE:` footer. See [CONTRIBUTING.md](CONTRIBUTING.md)
for the local commitlint hook setup and CI checks. Fix validation errors;
never bypass the hook to accept an invalid message.
